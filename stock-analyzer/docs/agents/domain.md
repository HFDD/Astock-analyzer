# Domain Docs

这个仓库采用 **单一上下文** 布局。工程技能在探索代码前，应优先读取根目录的 `CONTEXT.md`，再按需查看 `docs/adr/` 中和当前工作有关的架构决策。

## 阅读顺序

1. 先读根目录 `CONTEXT.md`
2. 再读 `docs/adr/` 中和当前模块相关的 ADR
3. 如果当前工作会影响某个已写下的决策，先确认是否与现有 ADR 冲突

## 约定

- 没有 `CONTEXT-MAP.md`
- 没有多上下文拆分
- `CONTEXT.md` 是全局词汇和术语来源
- `docs/adr/` 只放长期有效的架构决策

## 术语使用

写 issue、测试名、重构提案时，优先沿用 `CONTEXT.md` 里的术语。不要轻易用同义词替换项目已经定下来的词。

## 发现 ADR 冲突时

如果当前输出和已有 ADR 不一致，要明确指出，而不是悄悄覆盖。

示例：

> _与 ADR-0007 的结论冲突，但值得重新讨论，因为……_
